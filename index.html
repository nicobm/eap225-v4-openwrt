Part 1

01

Flashing OpenWrt on the EAP225 v4

Replace TP-Link's stock firmware with OpenWrt. This section is specific to the EAP225 v4 hardware and requires physical access: serial console + soldering.

Overview

OpenWrt officially supports the EAP225 v4 (target ath79/generic) since 2022. The standard software installation method (SSH + cliclientd stopcs) works only on firmware ≤ 5.1.6. Firmware 5.2.x blocks it: TP-Link replaced the Linux shell with a restrictive proprietary CLI and removed cliclientd.

The only confirmed method for firmware 5.2.x is serial console + U-Boot + TFTP: bypass the stock firmware entirely by talking to the bootloader over the PCB's serial port.

This guide targets firmware 5.2.3 (Build 20250709). Downgrade to previous versions is explicitly forbidden by 5.2.x, so there is no software way back.

!

3.3V only

The EAP225 v4 SoC (QCA9563) runs at 3.3V. A 5V USB-UART adapter can permanently damage it. Verify your adapter with a multimeter before connecting anything.

!

No factory recovery

After flashing OpenWrt there is no TP-Link recovery mode. Keep a full flash backup if you want to go back to stock (requires an SPI programmer otherwise).

!

Bricking risk

A power loss during flashing can brick the device. Use a stable PoE source and do not disconnect anything during the process.

What changed in firmware 5.2.x

On firmware ≤ 5.1.6, SSH gave a full Linux shell where you could run cliclientd stopcs and then flash OpenWrt from the web UI. From 5.2.x onward TP-Link:

  • Removed the Linux shell over SSH — now a proprietary CLI (prompt EAP> / EAP#) like Cisco.
  • Removed the cliclientd command — it does not exist in the new CLI.
  • Blocked downgrade — cannot roll back to any previous version.
  • Linux commands (ls, cat, sh) do not work; enable only exposes diagnostic show commands.

Materials

Hardware

  • USB-to-UART adapter (3.3V) — CP2102, FT232RL or CH340G. Must be 3.3V.
  • Dupont jumper wires.
  • Soldering iron + solder — J4 pads likely have no pins; solder pin headers or wires.
  • Ethernet cable — direct PC ↔ EAP225.
  • PoE injector or PoE switch — to power the EAP225.

Software

  • picocom — serial terminal.
  • dnsmasq — TFTP server.
  • OpenWrt images for EAP225 v4 (initramfs + sysupgrade).

Install the tools with your distribution's package manager, e.g.:

sudo apt install picocom dnsmasq wget   # Debian/Ubuntu
sudo dnf install picocom dnsmasq wget   # Fedora
sudo pacman -S picocom dnsmasq wget     # Arch

Add your user to the dialout group to access /dev/ttyUSB* (log out and back in after):

sudo usermod -aG dialout $USER

Verify the USB-UART adapter (multimeter)

Many cheap adapters claim 3.3V but ship configured for 5V. Verify before connecting.

  1. Plug the adapter into the PC (nothing connected to the other end).
  2. Set the multimeter to DC voltage (20V range or auto).
  3. Measure VCC: red probe on VCC, black on GND. Expected ~3.3V (3.0–3.6). If ~5.0V → do NOT use.
  4. Measure TXD at idle: red probe on TXD, black on GND. Expected ~3.3V.
!

Golden rule

If any reading is above 3.6V, do not connect that adapter to the EAP225. Get one that runs natively at 3.3V (CP2102 and FT232RL usually do).

Flash guide (serial + TFTP)

1

Download the OpenWrt images

mkdir -p ~/openwrt-eap225v4 && cd ~/openwrt-eap225v4

# initramfs (temporary boot from RAM)
wget https://downloads.openwrt.org/releases/23.05.5/targets/ath79/generic/openwrt-23.05.5-ath79-generic-tplink_eap225-v4-initramfs-kernel.bin -O initramfs.bin

# sysupgrade (permanent install)
wget https://downloads.openwrt.org/releases/23.05.5/targets/ath79/generic/openwrt-23.05.5-ath79-generic-tplink_eap225-v4-squashfs-sysupgrade.bin -O sysupgrade.bin

Check the latest stable release on the firmware selector searching "EAP225 v4" and adjust the URLs.

2

Open the EAP225 and wire the serial

  1. Disconnect power (unplug PoE).
  2. Open the case — remove the rear screws.
  3. Locate header J4 on the PCB — 4 aligned pads:
J4: [ Pin1: TXD ] [ Pin2: RXD ] [ Pin3: GND ] [ Pin4: VCC ]

You may need to bridge unpopulated resistors R225 (TXD line) and R237 (RXD line). Solder pins or wires to J4, then connect:

EAP225 J4 Pin1 (TXD)  →  RXD of the USB-UART adapter
EAP225 J4 Pin2 (RXD)  →  TXD of the USB-UART adapter
EAP225 J4 Pin3 (GND)  →  GND of the USB-UART adapter
EAP225 J4 Pin4 (VCC)  →  DO NOT CONNECT (powered by PoE)
3

Open the serial terminal

ls /dev/ttyUSB*
picocom -b 115200 /dev/ttyUSB0

Exit picocom with Ctrl+A then Ctrl+X. Do not power the EAP yet.

4

Configure the network and TFTP server

Connect the PC directly to the EAP225 with an ethernet cable.

Set a static IP on your PC:

sudo ip addr add 192.168.1.10/24 dev eth0   # replace eth0 with your interface

Open the firewall for TFTP:

sudo firewall-cmd --add-service=tftp   # or ufw allow 69/udp

Start the TFTP server (keep this terminal running):

mkdir -p /tmp/tftp
cp ~/openwrt-eap225v4/initramfs.bin /tmp/tftp/
sudo dnsmasq --no-daemon --port=0 --enable-tftp --tftp-root=/tmp/tftp --listen-address=192.168.1.10
5

Access the U-Boot bootloader

  1. Have picocom open in another terminal.
  2. Connect PoE power to the EAP225.
  3. Immediately press Ctrl+B repeatedly in the serial terminal.
  4. If you succeed, the U-Boot prompt appears:
ath>

If it boots into stock firmware, disconnect PoE, wait a few seconds, reconnect while spamming Ctrl+B.

6

Load OpenWrt over TFTP

At the ath> prompt:

ath> setenv ipaddr 192.168.1.1
ath> setenv serverip 192.168.1.10
ath> tftp 0x80800000 initramfs.bin
ath> bootelf $fileaddr
  • setenv ipaddr — IP used by the EAP225 for the transfer.
  • setenv serverip — IP of your PC (TFTP server).
  • tftp — downloads the image into the EAP225's RAM.
  • bootelf — boots OpenWrt from RAM.

This is temporary — OpenWrt runs from RAM and has not touched the flash yet. The dnsmasq terminal shows the transfer; the serial terminal shows the kernel booting.

7

Install OpenWrt permanently

OpenWrt now runs (temporarily) and is reachable at 192.168.1.1.

Option A — via SSH (recommended)

ping -c 3 192.168.1.1
scp ~/openwrt-eap225v4/sysupgrade.bin root@192.168.1.1:/tmp/
ssh root@192.168.1.1
# inside the device:
sysupgrade -v /tmp/sysupgrade.bin

Option B — via web UI (LuCI)

  1. Open http://192.168.1.1.
  2. Go to System → Backup/Flash Firmware.
  3. Upload sysupgrade.bin and confirm.

The device reboots and this time boots OpenWrt from internal flash.

8

First login to OpenWrt

  1. Wait for the LED to stabilize.
  2. Go to http://192.168.1.1.
  3. User: root, no password.
  4. Set a password immediately under System → Administration.
9

Clean up

# Remove the temporary network connection:
sudo ip addr del 192.168.1.10/24 dev eth0

# Stop dnsmasq: Ctrl+C in its terminal
# Exit picocom: Ctrl+A, Ctrl+X

Troubleshooting

  • Cannot interrupt U-Boot (Ctrl+B): retry, disconnecting and reconnecting PoE while spamming Ctrl+B.
  • TFTP transfer fails: check firewall, IP addresses (192.168.1.1 / 192.168.1.10) and that dnsmasq is running.
  • No serial output: check TX/RX crossover (TXD→RXD), GND, baud rate 115200, and resistor bridges R225/R237.
  • Device does not boot after sysupgrade: re-run the TFTP process from step 5.

Back to stock / last resort

There is no TP-Link recovery mode after flashing OpenWrt. Options to restore stock firmware:

  • If you made a full flash backup before flashing, restore it with an SPI programmer (clip SOIC-8 + CH341A at 3.3V, or Raspberry Pi + flashrom).
  • Otherwise, re-flashing stock requires the original firmware image written to the SPI-NOR chip directly.

U-Boot is not blocked on this device, so the serial method remains available even after a bad flash.

Part 2

02

First boot & basic configuration

Minimal steps after OpenWrt is running. Everything else is fine on its defaults.

First boot

  1. Wait for the LED to stabilize after sysupgrade.
  2. Browse to http://192.168.1.1 (LuCI). Log in as root with no password.
  3. Set a root password: System → Administration.
  4. Enable Wi-Fi if needed: Network → Wireless → enable the radios (radio0 2.4 GHz, radio1 5 GHz).

Basic configuration

Only the settings that change. The EAP225 is an access point, so keep it simple.

  • Set the device as a dumb AP if you already have a router: disable DHCP on LAN, assign a static IP in your subnet, and bridge the wireless interfaces to LAN.
  • Set the timezone and NTP: System → System → Timezone; Services → NTP (or install chrony-nts for NTS).
  • Update packages: System → Software → Update lists, then upgrade.

Flashing method based on the OpenWrt community work for the EAP225 (serial console + U-Boot + TFTP). See the OpenWrt wiki and forum threads. Licensed under GPL-2.0.
